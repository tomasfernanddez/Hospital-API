# Tarea 013 · API de usuarios con PostgreSQL

API REST de usuarios con persistencia real en PostgreSQL, Sequelize como ORM y DTO de entrada y salida validados con Yup.

Patrón clásico de Express: `Route → Middleware → Controller → Model → PostgreSQL`.

## Stack

| Pieza      | Versión                         |
| ---------- | ------------------------------- |
| Node.js    | 26.x (ES Modules)               |
| Express    | 5                               |
| PostgreSQL | 16.15 (Docker)                  |
| Sequelize  | 6 (`pg` + `pg-hstore`)          |
| Yup        | 1                               |

## Requisitos

- [Node.js 26](https://nodejs.org/)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) abierto
- Un cliente de PostgreSQL (TablePlus, DBeaver, pgAdmin) para crear la tabla

## Levantarlo desde cero

### 1. Clonar e instalar

```bash
git clone https://github.com/tomasfernanddez/Hospital-API
cd Hospital-API
npm install
```

### 2. Crear el `.env`

Docker Compose y la API leen **solo** `.env`, no `.env.example`.

```bash
cp .env.example .env        # PowerShell: copy .env.example .env
```

Editá `DB_PASSWORD` con el valor que quieras. Ese mismo valor se usa en el cliente SQL.

| Variable      | Ejemplo                 | Para qué                               |
| ------------- | ----------------------- | -------------------------------------- |
| `PORT`        | `3000`                  | Puerto de la API                       |
| `CORS_ORIGIN` | `http://localhost:5173` | Orígenes permitidos, separados por coma |
| `DB_HOST`     | `127.0.0.1`             | Host de PostgreSQL                     |
| `DB_PORT`     | `5433`                  | Puerto publicado por el contenedor     |
| `DB_NAME`     | `nodepgdb`              | Base que crea el contenedor            |
| `DB_USER`     | `postgres`              | Usuario por defecto de la imagen       |
| `DB_PASSWORD` | `change_me`             | Password del usuario `postgres`        |
| `DB_LOGGING`  | `false`                 | `true` imprime el SQL generado         |

> Se usa `5433` en lugar de `5432` para no chocar con un PostgreSQL instalado localmente. Si no tenés uno, podés usar `5432`.

### 3. Levantar la base

```bash
docker compose up -d --wait
```

Cuando termina con `Container nodepgdb Healthy`, la base está escuchando en `127.0.0.1:${DB_PORT}`.

Los datos se guardan en `./postgres/`, que está en `.gitignore`. Sobreviven a `docker compose down`.

### 4. Crear la tabla

Conectá el cliente SQL con los datos del `.env` (host `127.0.0.1`, puerto `DB_PORT`, usuario `postgres`, base `nodepgdb`) y ejecutá:

```sql
CREATE TABLE users (
  id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(120) NOT NULL,
  email VARCHAR(255) NOT NULL UNIQUE,
  password VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

Los usuarios se crean con `POST /api/users`: el password se guarda hasheado con bcrypt, así que no se pueden insertar a mano.

Sin cliente gráfico, lo mismo desde la terminal:

```bash
docker exec -it nodepgdb psql -U postgres -d nodepgdb
```

### 5. Arrancar la API

```bash
npm run dev
```

```text
Database connection established → nodepgdb
Server is running on http://localhost:3000
```

Si la base no responde, el proceso termina al arrancar con `Failed to start server: ...` y código de salida `1`.

| Script        | Qué hace                                  |

| `npm run dev` | Arranca con `node --watch` (recarga sola) |
| `npm start`   | Arranca sin recarga                       |

## Endpoints

Base: `http://localhost:3000/api`

| Método   | Ruta                       | Body                | Respuesta OK |
| -------- | -------------------------- | ------------------- | ------------ |
| `GET`    | `/health`                  | —                   | `200`        |
| `GET`    | `/users`                   | —                   | `200`        |
| `GET`    | `/users/search?keywords=`  | —                   | `200`        |
| `GET`    | `/users/:id`               | —                   | `200`        |
| `POST`   | `/users`                   | `{ name, email, password }`    | `201` + `Location` |
| `PATCH`  | `/users/:id`               | `{ name?, email?, password? }` | `200`        |
| `POST`   | `/auth/login`              | `{ email, password }`          | `200`        |
| `DELETE` | `/users/:id`               | —                   | `204`        |

Las respuestas exitosas usan `{ "data": ... }` y solo exponen `id`, `name` y `email`.

`search` busca en `name` y `email` sin distinguir mayúsculas. Sin `keywords` devuelve `[]`.

### Errores

Todos con la forma `{ "error": { "code", "message", "details?" } }`.

| Status | `code`             | Cuándo                                              |
| ------ | ------------------ | --------------------------------------------------- |
| `400`  | `VALIDATION_ERROR` | Body inválido, campos desconocidos o `PATCH {}`     |
| `400`  | `INVALID_ID`       | El `:id` no es un entero positivo                   |
| `400`  | `INVALID_JSON`     | JSON mal formado                                    |
| `401`  | `INVALID_CREDENTIALS` | Email o password incorrectos (mismo mensaje para los dos) |
| `404`  | `USER_NOT_FOUND`   | El usuario no existe                                |
| `404`  | `ROUTE_NOT_FOUND`  | La ruta no existe                                   |
| `409`  | `EMAIL_TAKEN`      | El email ya está registrado                         |
| `500`  | `INTERNAL_ERROR`   | Error inesperado                                    |

### Ejemplo

```bash
curl -i -X POST http://localhost:3000/api/users \
  -H 'Content-Type: application/json' \
  -d '{"name":"  Ada Lovelace ","email":" ADA@Example.com ","password":"12345678"}'
```

```json
{ "data": { "id": 3, "name": "Ada Lovelace", "email": "ada@example.com" } }
```

> En Windows, corré los `curl` desde **Git Bash**. En PowerShell, `curl` es un alias de `Invoke-WebRequest` y las comillas del `-d` se rompen.

## Estructura

```text
src/
├── app.js            # Arma la app: CORS, JSON, rutas, 404 y errores
├── server.js         # Conecta a la base, escucha y cierra el pool al salir
├── config/           # Conexión de Sequelize (lee el .env)
├── models/           # Modelo User ↔ tabla users
├── dtos/             # Contratos de entrada (Yup) y de salida
├── errors/           # AppError
├── middlewares/      # Validación de body e id, 404 y manejo de errores
├── controllers/      # Traduce HTTP ↔ modelo
└── routes/           # Paths y middlewares por endpoint
```

## Problemas frecuentes

| Síntoma | Solución |
| ------- | -------- |
| `password authentication failed` y en `docker compose logs db` aparece `Skipping initialization` | `./postgres/` se creó antes con otro password. Corré `docker exec -it nodepgdb psql -U postgres -c "ALTER USER postgres PASSWORD 'tu_password';"` o borrá `./postgres/` con el contenedor detenido y volvé a levantar |
| `port is already allocated` | Otro proceso usa ese puerto. Cambiá `DB_PORT` en el `.env` |
| `ECONNREFUSED 127.0.0.1:<puerto>` | El contenedor no está corriendo: `docker compose up -d --wait` |
| `relation "users" does not exist` | Falta crear la tabla (paso 4) |
| El cliente SQL no muestra la tabla | Refrescá el panel (`Ctrl + R` en TablePlus) |
